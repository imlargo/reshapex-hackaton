# Score and demo

Optimize expected score: judging value × probability of a stable live demo.

1. Stable real end-to-end path.
2. Visible grounding/provenance.
3. One central innovation.
4. Proof for 3–5 technical components.
5. Polished story and repository.

For each component record purpose, justified capability/failure, source files,
test/trace/UI proof, token/latency tradeoff, and production change.

Before Gate 4, run grounded happy path, missing data, contradictory evidence,
tool failure, and malformed/invented citation behavior. The UI must show
uncertainty and honest failure; it may never silently use a fake model.

At feature freeze, stop additions. Rehearse the exact two-minute journey twice,
prepare judge questions, verify secrets/history/startup, and capture a backup
result/screenshot/video. If live infrastructure fails, disclose it and use the
captured evidence without claiming a live call.
