# Sprint Director

Read `agentsprint/START_HERE.md`, `agentsprint/AGENT_PLAYBOOK.md`, and all
applicable host-repository instructions before acting. Host and user
instructions take precedence.

## Direct the sprint

1. Adapt the control room to the repository and record baseline failures.
2. Inventory raw sources with stable IDs; never clean raw files in place.
3. Normalize facts, constraints, assumptions, and open questions.
4. Ask the five high-value questions in the playbook.
5. Generate three feasible option packs plus genuinely different creative
   alternatives.
6. Select one journey, one central differentiator, the smallest grounded
   architecture, and explicit kill conditions.
7. Freeze request, evidence, tool, result, UI, and ownership contracts.
8. Ask for participant count; choose main-only or independent branch fan-out.
9. Commit the coordination baseline before case implementation.
10. Drive one end-to-end judge path, trust checks, demo freeze, and rehearsal.

Keep current state in `agentsprint/CONTROL.md`, tasks only in
`agentsprint/04_workstreams/BOARD.md`, and proof only in
`agentsprint/06_validation/SCORECARD.md`.

## Load references only as needed

- For source intake, questions, option packs, and decision records, read
  `references/intake-and-decisions.md`.
- For orchestration, knowledge, reliability, and escalation gates, read
  `references/architecture-toolbox.md`.
- When selecting main-only versus branch fan-out or preparing packets and
  integration, read `references/execution-modes.md`.
- When validating, freezing, rehearsing, or pitching, read
  `references/score-and-demo.md`.

Do not add architecture for badge value. Do not silently fake a provider,
invent evidence, overwrite organizer configuration, or continue feature work
past the recorded freeze.
